    ADR-0003: ServerSpec, 서버 정의를 하나로¶
    상태 system-architect 리뷰 후 수정하여 승인(2026-10-23). PR 1·2(#754), PR 3(feature/675-provision)으로 구현
    이슈 #675(강건화 D5, 마일스톤 M4 #645). #715 S8(create-server.sh 교체) 포함
    바꾸는 ADR ADR-0001: IServerSpecRepository에 load/write 추가(v2 메서드 유지), IHostnameRegistrarPort.register/unregister 추가
    기반 ADR-0002(#670, 배정의 원천은 LEVEL. PR #750으로 머지됨), PR #749(#656: env 코덱, atomicWriteFile, API 생성·삭제 대기열), #651, #649, #654, #751(avahi sudoers 모양)
    관련 #735(S7 삭제), #657, #658, #736(S9, v3.0.0), #641(k8s), #655, #737, #726

    영어판이 원본이다. 이 문서는 결정과 표를 줄여 옮겼다.

    배경¶

    • 서버 하나의 정의가 7곳(config.env, 서버 compose, include 목록, .env, .mcctl.json, avahi hosts, 잠금 파일)에 흩어져 있고, 쓰는 코드가 10곳이 넘는다. 그중 4곳은 compose YAML을 정규식으로 고친다(B4).
    • create-server.sh(789줄)는 cp와 sed로 서버를 만들고, 실패하면 servers/<n>을 남기며(#657), API가 해석할 수 없는 진행 문자열을 낸다(#658).
    • k8s 어댑터(#641)는 런타임과 무관한 정의 하나에서 매니페스트를 만들어야 한다(계획서 §12 조건 3).

    결정 요약¶

    1. servers/<n>/server.yaml이 정의다. config.env, 서버 docker-compose.yml, include 항목은 여기서 생성한다. 플랫폼 파일(.env, 메인 compose, .mcctl.json)은 스펙에 넣지 않는다.
    2. 작은 타입 필드 + env 통과값. mcctl이 판단하거나 렌더러가 변환해야 하는 것(type, version, memory, image, world, routing)만 타입으로 둔다. 나머지 config.env 키는 env에 그대로 두므로 가져오기에서 손실이 없다.
    3. v2.x에서 읽는 코드는 바꾸지 않는다. 저장할 때마다 생성물을 다시 쓰므로 기존 리더는 계속 config.env와 compose를 읽는다. 쓰는 코드만 옮긴다.
    4. 손으로 고친 내용은 잃지 않고 흡수한다. 헤더 해시로 감지한다. config.env 수정과 compose의 스펙 소유 필드(image, mc-router.* 라벨) 수정은 다음 쓰기 전에 스펙에 흡수한다. 그 밖의 compose 차이는 보호하고 조용히 덮어쓰지 않는다.
    5. 새 포트도, 깨지는 export도 없다(#715, v2.x 규칙). IServerSpecRepository와 ServerSpec은 v2 모양을 유지한다. 전체 타입은 새 이름 ServerSpecDocument이고, 새 동작은 메서드 추가(load, write)로 얻는다. #670이 IWorldAssignmentPort에 쓴 방식과 같다. 렌더링은 저장소 어댑터 안의 인프라 세부 사항이다. IHostnameRegistrarPort에 register를 추가한다(unregister는 #735에서 삭제와 함께 추가).
    6. 잠금 파일 없음. 생성은 mkdir로 디렉터리를 선점하고, 수정은 낙관적 리비전(server.yaml의 sha256)으로 충돌을 막는다. #749의 API 내부 대기열은 그대로 둔다.
    7. 가져오기는 지연 또는 명시적으로만, 일괄로 하지 않는다. server.yaml이 없는 서버는 첫 쓰기 때 메모리에서 가져오고, mcctl migrate spec으로 요청할 때 가져온다. mcctl upgrade는 아직 가져오지 않은 서버를 보고만 한다. 한 번도 가져오지 않은 서버도 지금처럼 동작한다.
    8. provision이 create-server.sh를 대신한다. CreateServerUseCase 안에서 API SSE가 이미 쓰는 이름으로 진행 이벤트를 내고, 실패하면 전부 되돌려 바로 다시 시도할 수 있게 한다.

    확정된 질문(2026-10-23)¶

    # 질문 결정
    1 생성 성공 뒤 시작 실패 서버는 생성된 상태로 둔다. CLI는 원인을 출력하고 종료 코드 1. API는 성공으로 응답하되 server.status: 'created'와 warning을 담는다(SSE completed). 콘솔이 "이미 있음"으로 끝날 재시도를 권하지 않게 하기 위해서다
    2 compose 수동 수정 스펙 소유 필드는 흡수하고 나머지는 보호, --force는 .bak을 남기고 덮어씀. override 파일은 나중에 추가할 수 있다
    3 global.env/.env에서 상속된 EXTRA_ARGS 가져올 때 실제 값을 config.env에 고정하고 보고
    4 mcctl upgrade의 일괄 가져오기 하지 않는다. upgrade는 보고만, 가져오기는 지연 또는 mcctl migrate spec
    5 생성에 쓰는 템플릿 번들 템플릿만(#651). API는 <root>/servers/_template을 더 읽지 않는다
    6 계획서 §9.2와 다른 점 수용(§1)
    7 .mcctl.json의 avahiEnabled: false 스크립트처럼 무시
    8 unregister의 sudoers 모양 #751이 되돌린 README 모양 sudo -n sed -i <expr> /etc/avahi/hosts(ADR-0001)

    1. 스키마¶

    타입 정의와 YAML 예시는 영어판 §1을 그대로 쓴다. ServerSpecDocument extends ServerSpec: specVersion: 1, name, type, version?, memory?, image, world { level, storage: universe|data }, routing { customHostnames[], playitDomain?, autoScale { up, down }, asleepMotd?, loadingMotd? }, env.

    필드 생성 가져오기·가져온 스펙 저장
    name ServerName(DNS-1123, 예약어, #649), 디렉터리 이름과 같아야 함 EXISTING_SERVER_NAME_PATTERN
    world.level WORLD_NAME_PATTERN, *_nether/*_the_end 금지(ADR-0002) EXISTING_WORLD_NAME_PATTERN
    type, version, memory ServerType, MC_VERSION_INPUT_PATTERN(정식 버전, LATEST, 스냅샷·프리릴리스, API 생성 규칙과 같음), Memory env 값 규칙
    호스트명, playitDomain 호스트명 규칙(HostnameService에서 도메인으로 이동) 같음
    env 키·값 ENV_KEY_RE / assertEnvFileValue(#726), 그리고 config.env 작성기가 쓸 수 있는 값(PR 3 리뷰) ENV_KEY_RE / assertEnvFileValue
    • 생성은 엄격한 값 객체로, 가져오기는 지금 동작하는 값을 받아들이고 엄격 규칙 위반만 보고한다(C1 #7).
    • 관리 키(TYPE, VERSION, MEMORY, LEVEL, PLAYIT_DOMAIN)는 env에 둘 수 없다. env.EXTRA_ARGS에는 --universe를 넣을 수 없다(world.storage가 맡음).
    • 엄격한 파일: 알 수 없는 최상위 키와 문자열이 아닌 스칼라는 경로와 함께 거부한다(version: 1.21은 float이므로 따옴표를 쓰라고 안내).
    • 오류는 다음 행동을 알려 준다: ServerSpecError는 서버, 파일, 필드와 다음 단계(따옴표 추가, mcctl migrate spec <n> --force, mcctl 업그레이드)를 담는다. v2 { name }만 save에 넘기면 빠진 필드를 나열한 invalid_spec으로 실패한다.
    • specVersion: 선택 필드 추가는 올리지 않는다. 호환이 깨지면 올리고 읽을 때 메모리에서 변환한다. 더 높은 버전은 거부한다.
    • server.yaml 손수정은 허용한다. 그 서버에 대한 다음 mcctl 쓰기나 mcctl migrate spec <n>에서 반영된다. mcctl start는 렌더링하지 않는다.
    • 비밀값: 버전 1에는 secretRefs가 없다. 사용자가 config.env에 넣은 비밀값은 env에 들어가고, server.yaml은 config.env와 같은 파일 모드를 쓰며 API로 반환하지 않는다. #641이 선택 필드로 추가한다.
    • 계획서 §9.2와 다른 점(수용): world.source·modpack·whitelist는 env 키, imageTag 대신 image, stopGraceSec·resources는 A2/C3에서, 서버별 잠금 대신 낙관적 리비전.

    2. 저장소, 저장, 동시성¶

    • 포트(전문은 ADR-0001): v2 메서드 list(): Promise<ServerSpec[]>, get(@deprecated, v3.0.0에서 삭제), save(spec)(전체 문서인지 검사 후 write), delete는 그대로 둔다(#735가 선택 인자 { deleteWorld?, dryRun? }와 결과를 더함, v2 호출은 그대로 컴파일됨). #675가 load(name) → { document, revision, warnings }와 write(doc, { expectedRevision?, create?, force?, allowStorageChange? })를 추가한다.
    • servers/<n>/server.yaml, 고정 키 순서, atomicWriteFile(#749).
    • 생성: mkdir servers/<n>(재귀 아님)이 선점이다. EEXIST는 already_exists.
    • 수정: load가 읽은 바이트의 sha256을 revision으로 돌려주고, write는 시작할 때와 첫 쓰기 직전(호스트 주소, 가져오기, 월드 스냅샷 같은 await 검사가 모두 끝난 뒤)에 비교하고, 계획의 기준이 된 생성 파일도 그 시점에 다시 읽는다. 다르면 conflict이고 updateServerSpec이 한 번 재시도한다. ponytail: 남는 창은 atomicWriteFile의 임시 파일 쓰기와 fsync(밀리초)다. 갱신 유실이 실제로 보이면 서버별 잠금을 추가한다.
    • 월드 보호(R1, R7): 렌더링한 LEVEL이나 저장 위치가 현재 config.env와 다르면 write가 ADR-0002의 순수 함수 checkProposed를 렌더링한 config.env를 넣은 스냅샷으로 실행한다. IWorldAssignmentPort.preview와 같은 스냅샷 리더를 직접 쓴다(배정 어댑터가 이 저장소로 쓰므로 포트를 거치면 순환). 저장 위치 변경은 allowStorageChange 없이는 거부한다(storage_change). 이 옵션은 mcctl migrate worlds만 쓴다. 같은 쓰기에서 정지되지 않은 서버도 거부한다(어댑터에 넘긴 런타임으로 checkServerStopped, 런타임이 없거나 상태를 읽지 못하면 판단 불가). 그래서 mcctl migrate spec이 손으로 고친 world.level을 렌더링해도 ADR-0002 결정 5를 우회하지 못한다. 유스케이스의 정지 검사는 그대로 둔다.
    • 저장 순서: server.yaml 먼저, 그다음 생성물. 중간에 죽으면 생성물의 해시는 맞고 spec=만 이전 값이므로(§3), 다음 쓰기나 mcctl migrate spec이 다시 렌더링해 마무리한다.

    3. 렌더링¶

    • 경계: 인프라 내부 인터페이스 ServerSpecRenderer { render(doc, ctx) }. FileServerSpecRepository가 생성자로 받는다. 애플리케이션 코드는 렌더러를 부르지 않으므로 포트가 아니다. 지금은 DockerComposeRenderer만 구현하고, KubernetesManifestRenderer(StatefulSet, Service, PVC)는 #641까지 인터페이스로만 둔다. #641은 렌더러와 함께 스펙 저장·매니페스트 적용에 필요한 k8s 저장소 어댑터를 추가한다. ADR-0001의 apply(spec)는 필요 없다. 삭제(#735)는 월드를 옮기기 전에 removeIncludeEntry로 생성된 include 항목 <n>/docker-compose.yml(남은 항목이 없으면 include: 자체)을 지우고(그 서버의 손으로 쓴 항목이 있으면 거부), 옮긴 뒤 servers/<n>을 지운다. ADR-0001 S7 참고.
    파일 방법 수정 감지
    config.env 현재 내용(생성 시 번들 템플릿)에 applyEnvChanges(..., { raw: true }). 값이 다른 키만 바꾸고 스펙에 없는 키는 지운다. 손대지 않은 줄은 바이트 그대로 예
    docker-compose.yml 번들 _template/docker-compose.yml을 js-yaml로 읽어 서비스 키·container_name, image, 라우터 라벨을 설정하고 dump 예
    servers/compose.yml js-yaml로 읽어 같은 항목이 없으면 추가, 다른 항목은 유지. CLI와 API 프로세스가 같은 파일에 서버를 추가하므로 읽기-병합-쓰기 전체를 servers/.compose.yml.lock(acquireFileLock, 백업 잠금과 같은 구현: link 기반, 이 호스트에서 죽은 것이 확실한 보유자는 인계, 약 10초 대기 뒤 locked) 안에서 한다. 잠금 안에서 파일을 새로 읽어 쓰고, 다시 읽어 원래 있던 항목과 새 항목이 모두 있는지 확인하며, 다르면 한 번 재시도. 읽지 못한 파일은 덮어쓰지 않고 아무것도 쓰기 전에 오류로 멈춘다 아니오(병합)
    data/, logs/, servers/global.env mkdir -p, global.env가 없으면 템플릿에서 복사 —
    • env 투영: TYPE, VERSION(없으면 생략, ''이면 VERSION=), MEMORY, LEVEL, PLAYIT_DOMAIN, EXTRA_ARGS, 그다음 env. universe면 EXTRA_ARGS = --universe /worlds/ + env.EXTRA_ARGS, data면 env.EXTRA_ARGS ?? ''.
    • 라우터 호스트명: <n>.local, hostIps마다 <n>.<ip>.nip.io, playitDomain, customHostnames(중복 제거). 이 생성기 하나가 build_hostnames, init.ts의 buildHostnames/mergeHostnames, HostnameService의 시스템 부분을 대신한다(B4).
    • 호스트 IP(resolveHostIps, shared 인프라, 스크립트와 같은 순서): .env의 HOST_IPS, 없으면 HOST_IP(env 코덱으로 읽음), 없으면 ip route get 1의 src 주소, 없으면 hostname -I의 첫 주소, 없으면(macOS) os.networkInterfaces()의 내부가 아닌 첫 IPv4. 모든 단계에서 docker0, br-*, veth* 주소는 건너뛴다. avahi에는 첫 주소를 쓴다.
    • 헤더(감지 대상 파일 첫 줄): # Generated by mcctl from server.yaml; edits are detected (ADR-0003). mcctl:sha256=<64 hex> spec=<12 hex>. 다른 상태 파일은 없다.
    • 멱등: 두 번 렌더링해도 같은 바이트이고, 스펙이 그대로면 쓰기가 없다.
    • 역할 분담(PR 2): 렌더러는 파일 본문만 돌려주고 ctx.read로 본문만 읽는다. 헤더는 저장소가 붙이고 검사하므로 렌더러는 헤더를 모른다. 리비전, 저장 위치, 수정 감지, 읽지 못한 servers/compose.yml 같은 모든 검사는 첫 쓰기 전에 끝난다. 쓰기가 중간에 실패하면 이미 바꾼 파일을 원래 내용으로 되돌리고(새로 만든 파일은 지움) 오류를 던진다. 단, 파일에 아직 이 쓰기가 쓴 내용이 있을 때만 되돌린다. 그사이(예: include 잠금 대기 중) 다른 writer가 고친 파일은 그대로 두고 메시지에 적는다. 정의 원천인 server.yaml은 생성 파일이 모두 되돌려졌을 때만 되돌리고, 아니면 새 스펙으로 둔다. 그래서 남는 상태는 전부 옛 내용이거나 새 스펙 + 일부 새 생성 파일뿐이고, mcctl migrate spec이 새 스펙으로 다시 렌더링한다. 되돌리지 못한 파일은 오류에 실린다(unrestoredFiles(error)). mcctl migrate worlds는 mcctl migrate spec이 렌더링할 스펙(load())이 가리키는 곳에 월드를 두고(새 스펙이면 worlds/에 두고, 이전 스펙이면 되돌리고, 그 밖이면 그대로 두고 확인할 것을 안내), 다음 시작 전에 mcctl migrate spec을 실행하라고 안내한다. 그 스펙과 server.yaml의 저장 위치가 다르면(mcctl migrate spec이 거부하는 경우) server.yaml을 지우고 mcctl migrate worlds를 다시 실행하라고 안내한다(PR 3 리뷰). FileServerSpecRepository.loadFile(name)(포트가 아닌 어댑터 메서드)은 흡수 없이 server.yaml만 읽고, mcctl migrate spec --force가 이것으로 server.yaml에서 다시 렌더링한다. server.yaml이 있으면 compose environment 항목은 스펙 소유가 아니므로 스펙 밖 수정으로 본다(가져오기는 여전히 옮긴다, §4).

    4. 기존 설치본 가져오기¶

    1. config.env: TYPE, VERSION, MEMORY, PLAYIT_DOMAIN은 타입 필드로. 빈 VERSION, MEMORY, PLAYIT_DOMAIN은 ''로 남겨, 렌더링한 KEY=가 계속 global.env보다 우선한다(PR 3 리뷰). world.level = resolveWorldName(env)(WORLD_NAME은 env에 남김). 나머지 키는 파일 순서대로 env에(알 수 없는 키 보존).
    2. 저장 위치: ADR-0002의 해석으로 실제 EXTRA_ARGS를 구한다. --universe /worlds[/]는 universe, 없음·/data·.는 data. --universe 토큰을 뺀 나머지는 env.EXTRA_ARGS로(global.env에서 왔으면 고정하고 보고). 디렉터리는 교차 확인만 한다.
    3. fail-closed: 보간되는 관리 키 값(${...})이나 다른 --universe 위치는 undetermined다. 그 서버는 가져오지 않고 계속 동작하며, 파일을 고칠 때까지 그 서버에 대한 쓰기는 이유와 함께 실패한다.
    4. compose: 서비스 mc-<n> 하나를 기대한다. image와 라우터 라벨은 routing으로, 호스트명은 시스템과 사용자 지정으로 나눈다. EULA가 아닌 environment 항목은 env로 옮긴다. Compose에서는 environment가 env_file보다 우선하므로 키가 겹치면 compose 값을 쓰고 보고한다. 스펙 소유 필드나 옮기는 environment 항목에 ${...}가 있으면 undetermined, 그 밖에 있으면 보호한다. $$는 Compose의 리터럴 $라 $로 읽는다. 렌더러는 compose에 넣는 $를 모두 $$로 쓰고, config.env 작성기는 $가 든 값을 작은따옴표로 감싸되, \로 끝나는 값은 거부한다(Compose는 \'를 이스케이프된 따옴표로 읽는다. PR 3 리뷰). §3의 의미 비교는 옮기거나 흡수한 항목을 뺀 compose로 한다.
    5. 보고: 서버마다 imported | refused(보호된 compose는 경고)와 경고(고정한 EXTRA_ARGS, environment 충돌, 다시 만든 옛 nip.io 호스트, 엄격 규칙 위반 값).

    실행 시점: load가 server.yaml이 없으면 메모리에서 가져오고 첫 쓰기가 파일을 저장한다(읽기는 쓰지 않는다). mcctl migrate spec [<name>|--all] [--dry-run] [--force]는 가져오기·흡수·렌더링을 하고 보고한다(멱등). mcctl upgrade는 server.yaml이 없는 서버와 migrate spec --dry-run 결과를 출력만 하고 아무것도 쓰지 않는다. 한 번도 가져오지 않은 서버는 v2.x에서 지금처럼 동작하고, 손으로 복사해 넣은 서버도 첫 쓰기에서 채택된다.

    PR 3 메모(구현 기준):

    • 렌더링한 서버 compose는 모든 문자열을 따옴표로 감싼다. v2 라벨 리더(parseRouterHosts, HostnameService)가 mc-router.host: "..." 형태로 찾기 때문이다.
    • §6의 쓰기 경로는 모두 updateServerSpec/setEnvKeys를 거친다. 예외는 setServerPlayitDomain(deprecated v2 export, mcctl은 더 이상 부르지 않음), server-env-migration(#736까지), config 스냅샷 복원이다. 복원은 일관된 묶음을 쓴다: 스냅샷과 mcctl server-backup에 이제 server.yaml이 들어가고, 그것이 없는 #675 이전 묶음은 다음 load에서 흡수한다. 쓰기 감시 테스트가 예외마다 이유를 적는다.
    • ConfigEnvWorldAssignmentAdapter는 생성자로 저장소를 받는다. 런타임이 있는 저장소가 없으면 LEVEL 변경을 거부한다(R7). 새 월드의 SEED도 같은 쓰기로 들어간다. WorldManagementUseCase가 assign에 넘긴다(#734).
    • CLI와 API는 테스트가 바꿔 끼울 수 있는 작은 팩토리(serverSpecRepositories, serverProvision)로 저장소를 만든다. 테스트는 docker, sudo, 실제 플랫폼 루트를 건드리지 않는다.
    • provision은 docker compose up에 30분 제한을 둔다(DockerComposeRuntimeAdapter의 startTimeoutMs). 첫 시작에 이미지를 받을 수 있고, 스크립트는 제한이 없었다.
    • 버전 없는 모드팩 타입은 VERSION을 쓰지 않는다(CLI는 LATEST를 넘겼다). 명시한 LATEST는 쓴다. API가 허용하는 스냅샷·프리릴리스 버전은 그대로 쓴다.

    8. 시험(TDD)¶

    각 PR에서 실패하는 시험을 먼저 추가한다. 세부 목록은 영어판 §8.

    • v2 호환: v2 계약으로 쓴 코드가 컴파일된다(const s: ServerSpec = { name: 'a' }, v2 타입으로 list/get/save/delete 호출). 패키지 루트가 ServerSpec과 IServerSpecRepository를 계속 export한다. save({ name })는 빠진 필드를 나열한 invalid_spec.
    • 도메인(검증표, buildCreateSpec 옵션별, 호스트명 생성기), 가져오기(옛 템플릿, 따옴표·주석·중복 키, 상속과 --universe 형식은 ADR-0002와 같은 fixture, 보간 거부, compose environment 충돌 보고, compose ${...}, image·라벨 흡수, 그 밖의 수정 보호), 렌더링(멱등, 스펙이 그대로면 쓰기 없음, 주석 보존, 헤더, 두 감지표, include 정확 일치·다시 읽기 재시도, 읽지 못한 servers/compose.yml 보존), 저장소(리비전 충돌·재시도, 선점, 실패 뒤 되돌리기와 재시도 성공, 월드 보호), 호스트 IP(우선순위, 가짜 바이너리로 탐지 순서, docker0/br-* 제외), provision·API(골든 동등성, 이벤트 순서, 시작 실패 → completed + created + warning, 이름에 error가 든 서버, sudoers와 같은 avahi argv, 비밀번호는 -S -v에만 쓰고 자식 환경에 넣지 않음), 스크립트 삭제(specRepo 없는 CreateServerUseCase와 ShellAdapter.createServer가 ENOENT가 아니라 "create-server.sh was removed in #675" 메시지로 실패), 쓰기 경로(§6 행마다 하나).

    결과¶

    • + 서버마다 정의가 하나이고 compose는 생성물이므로 k8s 작업(#641)은 호출처를 고치지 않고 렌더러를 추가한다.
    • + 호스트명 생성, env 쓰기, YAML 편집이 각각 구현 하나로 줄고 정규식 YAML 편집이 없어진다.
    • + 생성이 실패하면 스스로 정리하고, 실제 진행 상황을 알리며, bash 없이 동작한다.
    • + IServerSpecRepository/ServerSpec의 v2 소비자 코드가 그대로 컴파일된다.
    • − 렌더링된 compose와 servers/compose.yml의 주석은 사라진다.
    • − 스펙 소유 필드가 아닌 compose 수정이 있으면, 되돌리거나 강제로 다시 렌더링할 때까지 compose를 바꾸는 쓰기가 막힌다.
    • − 파생 상태 두 가지(헤더 해시, 리비전)가 정확해야 한다. 수정 감지표가 시험 계약이다.
    • − v3.0.0까지 저장소에 v2 get/save와 load/write가 함께 있다.

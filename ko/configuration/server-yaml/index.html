    서버 정의 (server.yaml)¶

    서버 하나는 파일 하나, servers/<이름>/server.yaml로 정의합니다. Docker Compose가 읽는 파일은 mcctl이 이 파일에서 만들어 씁니다.

    파일 server.yaml에서 생성
    servers/<이름>/config.env 예 (주석과 손대지 않은 줄은 그대로)
    servers/<이름>/docker-compose.yml 예 (번들 템플릿에서 생성)
    servers/compose.yml <이름>/docker-compose.yml include 항목만 추가하고 다른 항목은 유지

    플랫폼 파일(.env, 메인 docker-compose.yml, .mcctl.json)은 포함하지 않습니다.

    파일 내용¶

    specVersion: 1
name: survival
type: PAPER
version: "1.21.1"
memory: 4G
image: itzg/minecraft-server:java25
world:
  level: survival
  storage: universe        # worlds/<level>, "data"는 servers/<이름>/data/<level>
routing:
  customHostnames:
    - mc.example.com
  playitDomain: aa.example.com
  autoScale:
    up: true
    down: true
env:                       # 그 밖의 config.env 키를 그대로
  GAMEMODE: survival
  ENABLE_RCON: "true"
  MOTD: Welcome to survival! Your adventure begins here.
    • TYPE, VERSION, MEMORY, LEVEL, PLAYIT_DOMAIN은 별도 필드이며 env에 둘 수 없습니다.
    • EXTRA_ARGS는 world.storage(universe면 --universe /worlds/)와 env.EXTRA_ARGS로 씁니다. 항상 쓰므로 서버가 더 이상 .env에서 상속받지 않습니다.
    • mc-router 호스트는 <이름>.local, HOST_IPS(없으면 HOST_IP)의 주소마다 <이름>.<ip>.nip.io, playit 도메인, 사용자 호스트 순입니다.
    • YAML이 숫자나 불린으로 읽는 값은 따옴표로 감쌉니다(version: "1.21", ENABLE_RCON: "true"). 그렇지 않으면 mcctl이 해당 필드를 알려 줍니다.

    누가 쓰는가¶

    서버를 바꾸는 mcctl 명령과 웹 콘솔 동작은 모두 server.yaml을 거칩니다: mcctl create, mcctl config, whitelist, op, mod, playit domain, update, init --reconfigure, 월드 배정, migrate worlds, 콘솔의 설정·화이트리스트·모드·호스트명 화면.

    기존 서버¶

    이 변경 전에 만든 서버에는 server.yaml이 없습니다. 지금처럼 동작하고, mcctl이 처음 바꿀 때 가져옵니다. 지금 가져오고 보고서를 보려면:

    mcctl migrate spec --all --dry-run   # 가져올 내용 미리 보기
mcctl migrate spec --all             # 가져오고 파일 쓰기

    가져오기는 config.env 키를 하나도 잃지 않습니다. docker-compose.yml의 environment 항목은 env로 옮깁니다(Compose가 config.env보다 우선했으므로, 충돌은 보고합니다). 월드나 이미지를 ${...} 보간으로 정한 서버는 값을 리터럴로 바꿀 때까지 가져오지 않습니다. VERSION=처럼 빈 값은 비어 있는 채로 남깁니다(version: ""). 빈 값도 servers/global.env보다 우선하기 때문입니다. mcctl은 config.env 값의 $는 작은따옴표 안에(이런 값은 \로 끝날 수 없습니다), compose 이미지나 라우터 라벨의 $는 $$로 써서 Docker Compose가 보간하지 않게 합니다. mcctl upgrade는 아직 server.yaml이 없는 서버를 알려 줍니다.

    손으로 고친 경우¶

    생성 파일의 첫 줄은 해시가 든 헤더라서 mcctl이 손수정을 알아챕니다.

    • config.env를 고침: 다음에 mcctl이 그 서버를 바꿀 때 server.yaml로 가져옵니다.
    • docker-compose.yml의 image나 mc-router.* 라벨을 고침: 같은 방식으로 가져옵니다.
    • docker-compose.yml의 다른 부분(포트, 볼륨 등)을 고침: 파일을 보호합니다. 그 파일에 영향이 없는 변경은 그대로 두고, 파일을 다시 써야 하는 변경은 compose_edited로 실패하며 고친 필드를 알려 줍니다.
    • server.yaml을 고침: 다음에 mcctl이 그 서버를 바꿀 때, 또는 mcctl migrate spec <이름>으로 반영합니다.
    • config.env와 server.yaml을 둘 다 고침: edit_conflict. 한쪽 수정을 되돌리거나 mcctl migrate spec <이름> --force로 server.yaml에서 다시 만듭니다(config.env.bak / docker-compose.yml.bak을 남김).

    mcctl start는 파일을 다시 만들지 않고 디스크에 있는 대로 시작합니다.

    서버 생성¶

    mcctl create와 웹 콘솔은 server.yaml과 위 파일을 쓰고, avahi에 <이름>.local을 등록하며(실패는 경고), --no-start가 없으면 서버를 시작합니다. 서버가 만들어지기 전에 실패하면 아무것도 남기지 않아서 같은 생성을 바로 다시 시도할 수 있습니다. 서버는 만들어졌지만 시작하지 못하면 서버는 그대로 둡니다. CLI는 원인과 함께 종료 코드 1로 끝나고 콘솔도 알려 줍니다. mcctl start <이름>으로 시작하세요.
